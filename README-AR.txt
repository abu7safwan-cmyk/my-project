واصل WASIL — نسخة مطوّرة للتخطيط والتجربة المحلية

محتويات المشروع:
- index.html / style.css / script.js : المتجر الإلكتروني.
- admin.html / admin.css / admin.js : لوحة المؤسس المطوّرة.
- image/ : الصور الموجودة في النسخة الأصلية.
- database/schema.sql : مسودة مخطط قاعدة بيانات SQL Server كبداية للـ Backend.

ما تم تطويره في هذه النسخة:
1. الحفاظ على واجهة المتجر الأصلية وهوية واصل (RTL وTajawal والأزرق والبرتقالي).
2. تطوير لوحة المؤسس لتشمل نظرة عامة، المنتجات، المتاجر، التجار وطلبات الانضمام، الطلبات، التوصيل، العمولات، التقارير والإعدادات.
3. إضافة رفع صورة المنتج من الجهاز ومعاينتها؛ الصور تحفظ محلياً في المتصفح.
4. دعم تسجيل طلبات انضمام تجريبية والموافقة أو الرفض.
5. إضافة سجل تاجر تجريبي مع عمولة خاصة أو استخدام العمولة العامة.
6. إضافة تصور التوصيل المختلط: مندوبو واصل ومندوبو التجار.
7. فصل رسوم التوصيل عن عمولة المنتجات في السياسة المعروضة.
8. دعم تحديث حالة الطلب التجريبي وتصدير ملخص CSV يفتح في Excel.
9. إضافة مسودة SQL Server تشمل المستخدمين والمتاجر والتجار والمنتجات والطلبات والتوصيل والعمولات والتسويات وسجل العمليات.

طريقة التشغيل:
1. فك ضغط الملف.
2. افتح مجلد WASIL في Visual Studio Code.
3. شغّل index.html وadmin.html عبر Live Server.
4. استخدم نفس المتصفح ونفس عنوان Live Server للمتجر ولوحة الإدارة حتى تتشارك بيانات localStorage.
5. لوحة المؤسس: افتح admin.html.
6. المتجر: افتح index.html.

مهم جداً — حدود النسخة:
- هذه نسخة Frontend تجريبية، وليست منصة إنتاجية.
- البيانات تحفظ في localStorage على نفس المتصفح والجهاز فقط.
- لا يوجد Backend عامل أو API أو اتصال فعلي بقاعدة بيانات SQL Server.
- schema.sql مسودة تصميم، ويجب مراجعتها وتنفيذها ضمن مشروع Backend.
- لا توجد مصادقة حقيقية أو حماية صلاحيات على الخادم؛ لا تستخدمها مع بيانات عملاء أو معلومات سرية.
- الدفع الإلكتروني غير مربوط. لا تستقبل أموالاً من خلال هذه النسخة.
- الطلبات والسائقون والموافقات والمستحقات في اللوحة نماذج محلية للتجربة وليست عمليات حقيقية.
- رفع الصور يحفظ الصورة داخل تخزين المتصفح، وقد يمتلئ التخزين إذا كانت الصور كبيرة. حد الصورة 1.5MB.
- رقم واتساب التجاري في script.js يجب مراجعته وتغييره قبل استخدام زر واتساب. لا ترسل طلبات حقيقية قبل اختبار الرقم والرسالة والسياسات.

قرارات واصل المضمنة في التخطيط:
- تسجيل التاجر ذاتياً بموافقة المؤسس، مع إمكانية إنشاء حساب تاجر من المؤسس.
- لكل تاجر لوحة مستقلة وصلاحياته الخاصة في النسخة الخلفية.
- عمولة عامة مع تخصيص عمولة لكل تاجر.
- التسوية اليدوية ودعم التحصيل الإلكتروني بعد ربط مزود مناسب.
- التوصيل المختلط بين مندوبي واصل ومندوبي التجار.
- عمولة واصل على المنتجات فقط، ورسوم التوصيل منفصلة.
- التقارير اليومية والأسبوعية والشهرية والسنوية.
- الشراء من عدة متاجر يفترض أن ينشئ طلبات فرعية مستقلة لكل متجر؛ يحتاج هذا السلوك إلى تنفيذ Backend قبل اعتماده تشغيلياً.

الخطوات اللازمة للإطلاق الحقيقي:
1. بناء Backend آمن (مثلاً ASP.NET Core إذا اعتمدنا .NET).
2. تنفيذ قاعدة SQL Server وربطها بالخادم.
3. إنشاء تسجيل دخول وصلاحيات فعلية للأدوار.
4. تنفيذ APIs للمنتجات والسلة والطلبات والتوصيل والعمولات.
5. ربط بوابة دفع مناسبة عند توفرها والتحقق من متطلباتها.
6. اختبار الأمان والنسخ الاحتياطي والتشغيل.
